## 복구

단일 단계에 문제가 생기면 해당 단계 커밋을 `git revert <commit-sha>`로 되돌리십시오. 이후 단계가 선행 단계에 의존하면 **마지막 정상 커밋으로 새 브랜치를 생성**해 확인하는 편이 더 안전합니다. 기존 저장 데이터를 삭제하거나 `main`을 강제 푸시하지 마십시오.

## 단계 1

- 민물 수조가 상단 도구 막대와 겹치던 이동 범위를 확대하여 수정.
- 이벤트 전용 물고기는 일반 추첨에서 제외하며, 실제 이벤트 선택 경로는 보존.
- 배경 실루엣 추첨에서 신발·쓰레기·보물 등 특수 아이템 제외.
- 이벤트 물고기의 수조 30마리 성장 동반 이미지에 실제 로드된 텍스처 적용.
- `node --experimental-default-type=module --test tests/*.test.mjs` 테스트 추가.

## 단계 2

- 모바일 2행 헤더: 첫 줄에 골드·도감·사운드·상점, 둘째 줄에 목표. 가로 스크롤/숨김 제거.
- 휴대폰에서는 글자 축소 대신 보이는 정보를 두 줄로 배치, 주요 터치 영역 최소 약 44 CSS px.
- 퀴즈 및 상점 등 DOM 팝업은 뷰포트 높이 안에서 자체 스크롤.
- 시작 화면의 지역/메뉴 버튼과 낚시터 집으로 버튼의 터치 영역 확대.
- 기존 `fishingGameData` 저장 형식 유지.

## 단계 3

- `src/utils/FishPresentation.js`에서 기존 크기 등급(XS~XL)을 물고기 ID별 설정으로 분리하고 화면별 표시 폭을 계산함.
- `getFishSizeTier()`의 크기 판정을 원본 PNG 배율에서 분리하여 조합 도감의 크기 분류에도 적용함. **기존 크기 도감 분류는 일부 달라질 수 있음**.
- 낚시터 배경에 무리·바닥·돌진·활공·순간 추진·순항 움직임을 추가하고 접근/수족관 최소 크기를 조절함.
- 기존 파일의 원본 해상도는 그대로 유지함.

## 단계 4

- 초반 한 번 터치 포획을 줄이고, 후반 과도한 연타를 완화하는 등급별 목표 시간·최소 터치 횟수 설정.
- 보스는 제한시간 내 포획을 고려한 별도 목표 시간을 사용함.
- 지역별 12% 확률의 짧은 환경 연출(잔물결·그림자·빛)을 추가하되 골드·확률 경제는 변경하지 않음.
- 기본 포획은 기존 연타를 유지하며 새로운 조작을 강요하지 않음. 실제 손맛은 기기에서 추가 확인 필요.

## 단계 5

- 수족관 어종별 행동 편향(바닥·군영·활공·돌진·순간 추진) 적용, 방향 전환 시 짧은 몸체 변화와 벽·수조 경계 고려.
- 곰치의 숨은 자리에서 미세 움직임 추가.
- 돋보기 DPR을 2로 제한하고 캔버스 치수가 실제 변경될 때만 재할당, 복사 빈도 약 30fps 제한.
- 오래된 브라우저 검증 스크립트를 390px 터치 화면 기준으로 전면 갱신하고 GitHub Actions에 브라우저 실행 및 스크린샷 기록 추가.
- 저장 데이터 구조는 보존; `main`에 자동 병합하지 않음.

### 브라우저 테스트 보정

수족관에 산호 테마 장식이 완성된 테스트 픽스처는 처음 진입할 때 자동으로 가족 스토리로 전환된다. 수족관 상호작용을 테스트하는 픽스처에는 `coralThemeStory: true`를 설정하여 화면 전환이 정상 기능 검증을 방해하지 않도록 처리.
